# v0.1 final release review

Final release-gate review of `phlo-transform` as v0.1.0. Scope: verify the
baseline, run the full validation suite live, check packaging/install/
upgrade paths, and record a verdict. Not an architecture review.

This document now also carries the validation evidence that previously lived
in the intermediate review reports (convergence review, dbt-migration audit,
fresh-container validation, readiness report) — those files were removed
from the tree and their load-bearing findings folded in here.

### Performance (real Trino + Nessie + Iceberg, testcontainers on OrbStack, Apple M2 Pro)

|---|---|---|---|---|---|---|---|---|
| 100 | 1.2s / 1 call | 10.0s | 1.1s / 101 | 1.1s / 102 | 0.13s / 7 | 1.2s / 101 — 100% cached | 0.9s — 100 cached, 0 built | 1.3s / 1.6s — 95 cached + 5 built |

### Correctness evidence

Bugs found by actual use across the earlier audit passes, each locked in by
a regression test (full narratives removed with the intermediate reports;
the regressions remain):

- **`cached` was classification-only** — adoption now persists an
  environment-local record claiming the source run verbatim
  (`a_cached_run_adopts_the_verified_output_into_the_environment`,
  `a_cached_run_falls_back_to_build_when_identity_drifts`,
  `candidate_reuses_inherited_materialisations_without_rebuilding`).
- **Model versions were not portable across environments** — the catalog is
  an environment binding, not model content; target input is
  `schema.table|materialization` and semantics v3
  (`cache_reuse_matches_across_catalogs_on_the_same_content_slot`,
  `a_catalog_retarget_adopts_the_visible_output`,
  `a_catalog_retarget_without_verifiable_identity_rebuilds`).
- **Composite `@key a,b` generated per-column unique tests** — now one
  composite unique plus `not_null` per column
  (`a_composite_key_asserts_one_composite_unique`).
- **Source references bypassed the environment catalog**
  (`a_candidate_compile_qualifies_source_references`).
- **`ref delete` leaked the provisioned Trino catalog** — routed through
  `cleanup_candidate`; verified live in dogfood.
- **Trino had no `load_csv`** — implemented with RFC 4180 parsing, type
  inference, batched inserts.
- **Transient identity reads masqueraded as "no verifiable output"** —
  non-missing-relation errors now retry (150ms, 400ms) before reporting
  `None`; anything still unreadable fails closed to a build.
- **Nessie commit hiccups were never retryable** — `EXTERNAL`,
  `INSUFFICIENT_RESOURCES` and the Nessie signature inside
  `GENERIC_INTERNAL_ERROR` are retryable.
- **A catalog retarget left plans undetectably stale** — `Plan::staleness`
  also requires `compiled.target.display() == model.target`
  (`a_plan_is_stale_when_the_compilation_retargets_the_model`).
- **`retry_failed` dismissed now-cacheable failures** — `Build | Cached`
  counts as executable (`retry_failed_executes_a_now_cacheable_model`).
- **Promotion evidence ids were re-looked-up after the gates ran** — audits
  return the consulted record's id; no second read
  (`audit_evidence_ids_name_the_record_the_audit_consulted`,
  `a_promotion_records_the_evidence_ids_the_gates_evaluated`).
- **`translate --verify` exited 0 on failing output** —
  `translate_verify_failure_exits_nonzero`.
- **DuckDB `source_state` fingerprinted schema only** — appends invisible to
  the planner; now includes `count(*)`
  (`unqualified_source_appends_trigger_rebuilds_on_duckdb`).
- **Quadratic compile time** — resolver/type-analysis scans are indexed;
  5,000-model `check` 8.5s → 0.3s.
- **dbt `arguments:` test syntax, seed `ref()`, `dbt.date_trunc`** — all
  lowered correctly with fixtures (`dbt-seeds`, `dbt-jaffle`,
  `native-seeds`).

## Upgrade compatibility

Verified by hand-building realistic old state and opening it with the
installed binary:

- **SQLite** — a pre-evidence, pre-`effective_key`, pre-`output_identity`,
  pre-v3 database (no `evidence`/`promotions` tables, short column sets,
  `compiler_version='2'` record): opens cleanly; all tables created and
  columns added **additively**; the legacy row reads via `state model`
  (`Adapter: <unrecorded>`); `plan` then reports `compiler semantics changed`
  and rebuilds once — the documented one-time rebuild wave.
- **Postgres** — a faithful old schema (BIGINT counters, no `evidence` table,
  no `adapter`/`output_identity`/`effective_key_json`/`seq`/`plan_json`
  columns): `ensure_schema` adds everything non-destructively;
  `state runs`/`state model` read pre-existing rows correctly.
- **Artifacts** — `lineage_diff.json`, `environment*.json` and promotion
  `record_json` carry `#[serde(default)]` on every field added since they
  were first written (`base_kind`, `candidate`, `environment`, `created_at`,
  `catalog_status`, `catalog_owned_by_phlo`, `evidence`); old payloads
  deserialize. `manifest`/`plan`/`run`/`diff`/`branch_diff` artifacts are
  write-only — the tool never reads them back.
- **Intentional incompatibility** — none found beyond the designed ones:
  pre-v3 records hash-miss once and rebuild; records without
  `adapter`/`output_identity` can never authorise cache reuse (fail closed).

Edge case noted, not a blocker: pointing `--state postgres://` at a
*foreign* table named `runs` with incompatible column types kills the state
worker thread; the CLI exits `error: state store error: postgres worker
stopped`. Loud and contained — phlo-written schemas always used BIGINT
counters, so this only triggers on databases phlo never created.

## CI / release workflow

`ci.yml` is the release gate: fmt + clippy + `cargo test --workspace` + the
Postgres service tests + all five Docker e2e targets. `release.yml` fires only
on `v*` tags: builds the CLI for linux-x86_64, macOS arm64 and macOS x86_64,
packages tarballs, creates a GitHub release. Nothing auto-publishes crates or
tags anything.

Two fixes this pass:

- The x86_64 leg pinned `macos-13`, a runner image GitHub retired in
  December 2025 — moved to `macos-15-intel` so the tag build can still
  schedule.
- `cp README.md LICENSE "dist/$name/" 2>/dev/null || true` would have let a
  release silently ship without its license — now a hard failure if either
  file is absent.

## Known limitations

- Warm-plan cost is O(models × snapshot read): ~28s at 5,000 models on a
  small Nessie/Trino pair (`--since` stays sub-second).
- Postgres state has no TLS — trusted networks only.
- Nessie Iceberg catalogs cannot store views — views must materialise as
  tables.
- dbt dynamic Jinja is deliberately limited: macros/snapshots/`run_query` are
  `REVIEW`/`UNSUPPORTED`, never executed.
- No cross-adapter/cross-engine cache reuse by design.
- `plan --ref` on an unprovisioned candidate previews an empty target (a
  printed note explains `run --ref` provisions and may adopt).
- Daemon reload is a full recompile; responses terser than the CLI.
- DuckDB `source_state` fingerprints schema + row count: in-place updates
  that preserve row count are invisible (Iceberg snapshot IDs are the
  precise mechanism).
- `inspect`/`explain` without `--adapter` compile offline and can report a
  spurious `changed` status; pass `--adapter` for catalogue-enriched state.

## Release blockers

None known. (Real findings fixed in this pass: missing `LICENSE`, the

## Final verdict

**Ready for v0.1.0**

## Post-v0.1 priorities

1. Batched/alternative output-identity reads — the ~28s warm plan at 5k is
   the largest recurring cost; every candidate run pays it.
2. Postgres TLS support — required before shared state over untrusted
   networks.
3. Provisioned-candidate `plan` parity — show expected adoption without a
   preceding `run --ref`.
4. `state`/`state evidence` ergonomics — make the promotion → evidence id →
   payload join legible in human output.
5. Transient-resilience budget review at 10k+ models — confirm the
   150/400ms retry delays and `buffered(16)` window still suffice.
